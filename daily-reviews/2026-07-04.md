# LeetCode 今日复盘 - 2026-07-04

## 总体收获

今天最大的进步不是多做了几道题，而是开始从“背框架”转向“判断题目该用什么框架，以及框架为什么能用”。

最重要的一句话：

```text
先判断题型和约束，再决定框架。
```

## 1. 滑动窗口

对应题目：最长无重复子串。

核心框架：

```text
右指针扩张窗口
窗口不合法时，左指针收缩窗口
窗口合法时，更新答案
```

今天踩过的坑：

```text
收缩窗口时，不能只判断重复。
必须同时做：
1. 窗口计数 -1
2. left++
```

关键理解：

```text
滑动窗口通常依赖单调性。
```

如果数组全是正数，右边加数会让 sum 变大，左边删数会让 sum 变小，这种情况适合滑动窗口。

如果数组里有负数，这个单调性就没了，普通滑动窗口容易错。

## 2. 前缀和 + HashMap

对应题目：和为 K 的子数组。

这题不能用普通滑动窗口，因为数组可能有负数。

核心公式：

```text
当前前缀和 = sum
想找一段子数组和为 k
需要之前出现过的前缀和 = sum - k
```

`map` 的含义：

```text
前缀和 -> 这个前缀和之前出现过几次
```

关键代码：

```java
Map<Integer, Integer> map = new HashMap<>();
map.put(0, 1);

int sum = 0;
int ans = 0;

for (int num : nums) {
    sum += num;
    ans += map.getOrDefault(sum - k, 0);
    map.put(sum, map.getOrDefault(sum, 0) + 1);
}

return ans;
```

注意：

```text
map 是历史账本，不是最终答案。
ans 才是在数“前缀和两两相减等于 k”的次数。
```

## 3. 反转链表

核心四步：

```java
ListNode next = current.next;
current.next = prev;
prev = current;
current = next;
```

关键理解：

```text
next 只是临时保存后继节点，防止断链。
不要乱改 next.next。
```

常见错误：

```java
temp.next = head;
```

这会破坏链表结构，而且当 `temp == null` 时会空指针。

## 4. 二叉树层序遍历

核心框架：

```text
队列
每一轮先固定当前层 size
弹出这一层所有节点
把下一层节点入队
每层结束后加入结果
```

注意点：

```text
root == null 要先返回空结果
ArrayDeque 不能 offer null
result.add(level) 要放在每层 for 循环结束后
```

标准结构：

```java
while (!queue.isEmpty()) {
    int size = queue.size();
    List<Integer> level = new ArrayList<>();

    for (int i = 0; i < size; i++) {
        TreeNode node = queue.poll();
        level.add(node.val);

        if (node.left != null) queue.offer(node.left);
        if (node.right != null) queue.offer(node.right);
    }

    result.add(level);
}
```

## 5. Top K 高频元素

前半段是统计频率：

```java
Map<Integer, Integer> count = new HashMap<>();

for (int num : nums) {
    count.put(num, count.getOrDefault(num, 0) + 1);
}
```

真正考点是：

```text
怎么取出频率最高的 k 个元素。
```

小顶堆思路：

```text
堆里最多保留 k 个元素
频率低的在堆顶
超过 k 个就 poll 掉频率最低的
最后堆里剩下的就是 Top K
```

关键条件：

```java
queue.offer(num);

if (queue.size() > k) {
    queue.poll();
}
```

不是：

```java
if (queue.size() == k)
```

比较器含义：

```java
return count.get(a) - count.get(b);
```

表示频率小的优先级更高，会更早被弹出去。

## 6. 快速排序

核心步骤：

```text
选 pivot
partition，把比 pivot 小的放左边
pivot 归位
递归排序左右两边
```

递归必须有终止条件：

```java
if (start >= end) {
    return;
}
```

partition 里要注意：

```text
用当前 nums[index] 和 pivotValue 比较。
不要因为 swap 导致 pivot 值变化。
```

最坏情况：

```text
如果每次都选最左边当 pivot，数组本来有序时会退化成 O(n^2)。
```

平均情况：

```text
O(n log n)
```

优化：

```text
随机 pivot
取中间位置
三数取中
```

## 7. 岛屿数量

核心识别：

```text
这是 flood fill。
```

DFS 和 BFS 都可以。

最简洁的是 DFS 原地修改：

```text
遍历网格
遇到 '1'：
    岛屿数 +1
    DFS 把这一整座岛的 '1' 全部改成 '0'
```

关键理解：

```text
把 '1' 改成 '0' 本身就相当于 visited。
所以不一定需要额外备忘录。
```

DFS 框架：

```java
private static void floodFill(char[][] grid, int i, int j) {
    if (i < 0 || i >= grid.length || j < 0 || j >= grid[0].length) {
        return;
    }

    if (grid[i][j] != '1') {
        return;
    }

    grid[i][j] = '0';

    floodFill(grid, i + 1, j);
    floodFill(grid, i - 1, j);
    floodFill(grid, i, j + 1);
    floodFill(grid, i, j - 1);
}
```

## 8. 回溯和树形搜索

今天真正理解了：

```text
每次 backtrack 代表一个状态。
每个合法选择就是一条分叉。
递归就是沿着分叉继续往下走。
```

统一框架：

```java
backtrack(当前状态) {
    if (到达终点) {
        收集答案;
        return;
    }

    for (选择 : 当前所有可能选择) {
        if (选择不合法) {
            continue;
        }

        做选择;
        backtrack(下一个状态);
        撤销选择;
    }
}
```

括号生成：

```text
每一步最多 2 个选择：
1. 放 (
2. 放 )
```

N 皇后：

```text
每一行最多 n 个选择：
放在第 0 列、第 1 列、...、第 n-1 列
```

所以：

```text
括号生成是最多 2 叉树。
N 皇后是最多 n 叉树。
```

## 9. 括号生成

状态：

```text
path 当前字符串
leftUsed 已使用左括号数量
rightUsed 已使用右括号数量
```

剪枝：

```text
leftUsed < n 时，可以放 (
rightUsed < leftUsed 时，可以放 )
```

关键理解：

```text
任何前缀里，右括号数量都不能超过左括号数量。
```

如果用 `StringBuilder`，需要撤销选择：

```java
path.append('(');
backtrack(...);
path.deleteCharAt(path.length() - 1);
```

如果每次传新字符串：

```java
backtrack(path + "(");
```

就不需要手动撤销，因为每条分支都是新对象。

## 10. N 皇后

核心框架：

```text
一行一行放皇后
当前行尝试每一列
合法就放 Q
递归下一行
回来后撤销成 .
```

普通 `isValidQueen` 判断三个方向：

```text
同一列上方
左上斜线
右上斜线
```

不用检查：

```text
同一行，因为每行只放一个
下方，因为还没放过
```

三个集合优化：

```java
Set<Integer> cols = new HashSet<>();
Set<Integer> diag1 = new HashSet<>(); // row - col
Set<Integer> diag2 = new HashSet<>(); // row + col
```

含义：

```text
cols：哪些列已经有皇后
diag1：哪些 \ 方向斜线已经有皇后
diag2：哪些 / 方向斜线已经有皇后
```

为什么斜线可以这样表示：

```text
\ 方向斜线：row - col 相等
/ 方向斜线：row + col 相等
```

判断是否合法：

```java
if (cols.contains(col) || diag1.contains(row - col) || diag2.contains(row + col)) {
    continue;
}
```

放皇后：

```java
board[row][col] = 'Q';
cols.add(col);
diag1.add(row - col);
diag2.add(row + col);
```

撤销：

```java
board[row][col] = '.';
cols.remove(col);
diag1.remove(row - col);
diag2.remove(row + col);
```

这三个集合不是 DP 备忘录，更准确叫：

```text
约束集合
visited 集合
剪枝表
```

它们记录的是当前路径上已经占用的列和斜线，用来 O(1) 判断当前选择是否合法。
