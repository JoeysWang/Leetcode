## 12. 10. Regular Expression Matching

'.' 匹配任意单字符，'*' 匹配前一个字符零次或多次。

```java
public boolean regexMatch(String s, String p) {
    int m = s.length();
    int n = p.length();
    boolean[][] dp = new boolean[m + 1][n + 1];
    dp[0][0] = true;
    for (int j = 2; j <= n; j++) {
        if (p.charAt(j - 1) == '*') {
            dp[0][j] = dp[0][j - 2];
        }
    }

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            char pc = p.charAt(j - 1);
            if (pc == '*') {
                dp[i][j] = dp[i][j - 2];
                char prev = p.charAt(j - 2);
                if (prev == '.' || prev == s.charAt(i - 1)) {
                    dp[i][j] |= dp[i - 1][j];
                }
            } else if (pc == '.' || pc == s.charAt(i - 1)) {
                dp[i][j] = dp[i - 1][j - 1];
            }
        }
    }
    return dp[m][n];
}
```

## 13. 44. Wildcard Matching

'?' 匹配单字符，'*' 匹配任意长度字符串。

```java
public boolean wildcardMatch(String s, String p) {
    int m = s.length();
    int n = p.length();
    boolean[][] dp = new boolean[m + 1][n + 1];
    dp[0][0] = true;
    for (int j = 1; j <= n; j++) {
        if (p.charAt(j - 1) == '*') {
            dp[0][j] = dp[0][j - 1];
        }
    }

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            char pc = p.charAt(j - 1);
            if (pc == '*') {
                dp[i][j] = dp[i][j - 1] || dp[i - 1][j];
            } else if (pc == '?' || pc == s.charAt(i - 1)) {
                dp[i][j] = dp[i - 1][j - 1];
            }
        }
    }
    return dp[m][n];
}
```

## 14. 概念：进程、线程、文件描述符

## 17. Java 锁：synchronized

### 是什么

`synchronized` 是 Java 的**关键字**（不是类），JVM 层面实现，作用是给某段代码加**互斥锁**——同一时刻只让一个线程进。每个 Java 对象天生自带一把"内部锁"（monitor/管程），`synchronized` 就是去占用这把锁。

### 三种写法（关键是"锁哪个对象"）

```java
// 写法一：同步代码块，锁指定对象
synchronized (obj) {
    // 临界区
}

// 写法二：同步实例方法，锁 this（当前实例）
public synchronized void method() { ... }

// 写法三：同步静态方法，锁 Class 对象（全类唯一）
public static synchronized void method() { ... }
```

**最重要判别：两个线程要互斥，必须锁同一把锁（同一个对象引用）。** 新手最常错：

```java
// ❌ 每次进来都 new 一个，根本没锁住
synchronized (new Object()) { ... }

// ❌ 锁了不同实例的 this，互不影响
class Foo { public synchronized void f() {} }
new Foo().f();  // 线程1 锁 foo1
new Foo().f();  // 线程2 锁 foo2

// ✅ 锁同一个对象
private final Object lock = new Object();
synchronized (lock) { ... }
```

### wait / notify（必须配合 synchronized）

`wait/notify/notifyAll` 是 `Object` 的方法，每个对象都有，**必须在持锁时调**，否则抛 `IllegalMonitorStateException`：

```java
synchronized (lock) {
    while (!条件) {
        lock.wait();      // 释放 lock 的锁、挂起，被叫醒后重新抢锁
    }
    // 干活
    lock.notify();        // 叫醒一个在 lock 上 wait 的线程
}
```

### 两个核心特性

- **可重入**：同一个线程拿到锁后还能再拿（进嵌套 synchronized 块或调本类另一个 synchronized 方法），不会把自己锁死。计数器 +1，出一次 -1，归零才释放。
- **可见性**：持锁时读到主存最新值，释放锁前把本地修改刷回主存。所以不会出现"线程 A 改了变量、线程 B 读到旧值"。

### monitor 机制（加锁时发生了什么）

JVM 给每个对象配了：
- 一个 **Entry List**（入口集）：想拿锁但没抢到的线程在这里阻塞
- 一个 **Wait Set**（等待集）：调了 `wait()` 的线程在这里挂起

```
线程A 持锁干活中
线程B 调 synchronized → 进 Entry List 阻塞
线程A 调 wait()     → 释放锁，自己进 Wait Set 睡觉
   ↓ Entry List 里的 B 被唤醒，抢到锁
线程A 被别人 notify 后移出 Wait Set → 进 Entry List 重新抢锁
   ↓ 抢到 → 从 wait() 返回
```

注意：`notify()` **不会立刻释放锁**，只是"预约"叫醒——叫醒的线程要从 Wait Set 移到 Entry List，等当前线程**出 synchronized 块释放锁**后才能继续。

### 经典坑

1. **wait 用 if 不用 while**：`wait` 可能被虚假唤醒（spurious wakeup）或被错的 notify 叫醒，醒来必须**重新检查条件**。用 `while`，不用 `if`。
2. **notify vs notifyAll**：`notify` 只叫一个，多消费者场景可能叫醒同类导致别的消费者饿死。生产者-消费者一般用 `notifyAll` 保险。
3. **锁错对象**：字符串字面量、`new` 出来的临时对象、不同实例的 `this` 都是常见陷阱。锁对象用 `private final` 持有。
4. **字符串做锁**：`synchronized("abc")` 别用——字符串常量池导致全 JVM 同一个 `"abc"` 对象，可能和无关代码互斥，出现诡异死锁。
5. **锁释放时机**：只有"出 synchronized 块/方法"或"wait()"才释放。中途抛异常也会释放（异常也算跳出块）。

## 18. Java 锁：ReentrantLock 与 Condition

### ReentrantLock：synchronized 的升级版

它是一个普通 Java 类（`java.util.concurrent.locks` 包），干的事和 `synchronized` 一样——给代码加锁，同一时刻只让一个线程进。但更灵活。

**和 synchronized 的对比**：

| 维度 | synchronized | ReentrantLock |
|---|---|---|
| 语法 | 关键字，自动释放 | 类，手动 `lock`/`unlock` |
| 释放锁 | 出 `{}` 自动释放 | 必须**手动** `unlock()`，通常放 `finally` |
| 可打断 | 不能，死等 | 能，`lockInterruptibly()` |
| 超时 | 不能 | 能，`tryLock(3, SECONDS)` |
| 公平锁 | 不能 | 能，`new ReentrantLock(true)` 先到先得 |

**"可重入"**：同一线程拿到锁后还能再拿（锁里调另一个也要这把锁的方法），不会把自己锁死。`synchronized` 本来就可重入，名字只是强调它也有。

**标准用法**（三步：lock → try → finally unlock）：

```java
Lock lock = new ReentrantLock();
lock.lock();           // 加锁
try {
    // 临界区代码
} finally {
    lock.unlock();     // 必须放 finally，否则抛异常就永远不释放
}
```

### Condition：wait/notify 的升级版

和一把锁绑定的"等待队列"。线程在某个 Condition 上 `await()` 挂起，别的线程用 `signal()` 叫醒。功能上是 `wait/notify` 的翻版。

**API 对照表**（几乎一一对应）：

| synchronized 那套 | Condition 这套 | 干的事 |
|---|---|---|
| `obj.wait()` | `cond.await()` | 释放锁、挂起当前线程 |
| `obj.notify()` | `cond.signal()` | 叫醒一个在这个 condition 上等的线程 |
| `obj.notifyAll()` | `cond.signalAll()` | 叫醒所有在这个 condition 上等的线程 |
| 在 `synchronized(obj)` 里才能调 | 在 `lock.lock()` 持锁时才能调 | 否则抛 `IllegalMonitorStateException` |

**怎么造一个 Condition**：从锁上"生"出来——

```java
Lock lock = new ReentrantLock();
Condition condA = lock.newCondition();   // 绑定到 lock 上
Condition condB = lock.newCondition();
```

### 为什么需要 Condition（升级版的价值）

`notify()` 的问题是**叫不精准**——从这把锁的等待池里**随机**叫一个，你不知道叫醒的是谁。A、B 两类线程都在等时，可能想叫 B 结果叫醒了 A。

`Condition` 让你建**多个独立的等待队列**：

```
synchronized 模型:               Condition 模型:

  一把锁                          一把锁
   └─ 一个等待池                    ├─ condA 队列（A 线程在这等）
       (A、B 混在一起)              └─ condB 队列（B 线程在这等）
   notify 随机叫一个               signal 精准叫某个队列里的
```

### 两种等待路径（理解的关键）

同一把锁，两个线程都调 `lock.lock()`，**只有一个能进去，另一个阻塞在 lock.lock() 那行**（不是报错，是睡眠等待）。这是互斥。

除了"卡在 lock.lock()"，还有另一条等待路径——`await()`：

```
路径1: 在 lock.lock() 处等      → 等"锁被释放"
路径2: 在 cond.await() 处等     → 等"被 signal 叫醒"
```

`await()` 做两件事：①**先释放锁**（不然你拿着锁去睡觉，别人永远进不来）；②**挂起线程**等被 `signal()` 叫醒，叫醒后**重新抢锁**，抢到才从 `await()` 返回往下走。

**await 的真正作用**：当某个线程跑得太快、抢在对方前面又拿到锁、但标志位说"还没轮到你"时，让它主动睡觉让出 CPU，而不是死循环空转或死锁。

### 选型建议

默认 `synchronized`，遇到它满足不了的需求（超时、可中断、多 Condition 精准唤醒、公平排队）再换 `ReentrantLock`。JDK6 后 synchronized 优化充分，性能通常够用。

## 19. 实战：两个线程交替打印

两个线程交替输出 1..10：线程 A 打印奇数 1,3,5,7,9，线程 B 打印偶数 2,4,6,8,10。配套代码在 `src/main/java/wirte/两个线程交替打印.java`。

核心思路：**一个共享状态（轮到谁）+ 互相唤醒**。两个线程不能各打各的，必须有人"等"、有人"叫"。

### 方式一：synchronized + wait/notify

用一把锁 + 一个 boolean 标志位 `turn`。谁拿到锁但发现还没轮到自己就 `wait()`；打印完翻转标志并 `notify` 唤醒对方。

```java
final Object lock = new Object();
final boolean[] turn = {true};   // true 轮到 A(奇数)

Thread A = new Thread(() -> {
    for (int i = 1; i <= 10; i += 2) {
        synchronized (lock) {
            while (!turn[0]) {            // 没轮到我，等
                try { lock.wait(); } catch (InterruptedException e) { return; }
            }
            System.out.println("A: " + i);
            turn[0] = false;              // 翻转，轮到 B
            lock.notify();                // 唤醒 B
        }
    }
}, "Thread-A");

Thread B = new Thread(() -> {
    for (int i = 2; i <= 10; i += 2) {
        synchronized (lock) {
            while (turn[0]) {             // 没轮到我，等
                try { lock.wait(); } catch (InterruptedException e) { return; }
            }
            System.out.println("B: " + i);
            turn[0] = true;               // 翻转，轮到 A
            lock.notify();                // 唤醒 A
        }
    }
}, "Thread-B");

A.start(); B.start();
A.join(); B.join();
```

### 方式二：ReentrantLock + 两个 Condition

两个 Condition 各管一个线程，谁干完活就 `signal` 对方的 condition，自己再 `await`。比 `notify` 精准：能定向唤醒。

```java
Lock lock = new ReentrantLock();
Condition condA = lock.newCondition();   // A 在这等
Condition condB = lock.newCondition();   // B 在这等
boolean[] turn = {true};

Thread A = new Thread(() -> {
    for (int i = 1; i <= 10; i += 2) {
        lock.lock();
        try {
            while (!turn[0]) {
                condA.await();
            }
            System.out.println("A: " + i);
            turn[0] = false;
            condB.signal();              // 叫醒 B
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            lock.unlock();
        }
    }
}, "Thread-A");

Thread B = new Thread(() -> {
    for (int i = 2; i <= 10; i += 2) {
        lock.lock();
        try {
            while (turn[0]) {
                condB.await();
            }
            System.out.println("B: " + i);
            turn[0] = true;
            condA.signal();              // 叫醒 A
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            lock.unlock();
        }
    }
}, "Thread-B");

A.start(); B.start();
```

### 关键细节（面试常考）

1. **为什么用 `while (!turn[0])` 而不是 `if`？** `wait/await` 可能被虚假唤醒或被错误的 notify 叫醒。用 `while` 重新检查条件最安全；用 `if` 醒来就直接执行，可能在条件不满足时就打印了。
2. **为什么用 `boolean[] turn` 数组而不是 `boolean turn`？** Lambda 引用外部变量必须 `final`，不能改值；包一层数组，引用不变、内容可改，绕过限制。也可用 `AtomicBoolean`。
3. **两个 Condition 的意义？** `notify()` 没法指定叫醒谁。两个 Condition 让 A、B 各有各的等待队列，`condB.signal()` 精确叫醒 B，不会误叫同类。多生产者/多消费者场景这是刚需。
4. **标志位翻转时机**：打印完**立刻翻转 + 唤醒对方**，对方醒来一检查条件就成立，无缝衔接。

### 方式三：Semaphore（最短代码，了解即可）

两个信号量一个初始 1 一个初始 0，互相 `release`/`acquire`，连标志位都省：

```java
Semaphore sa = new Semaphore(1);  // A 先走
Semaphore sb = new Semaphore(0);
// A: sa.acquire() → 打印 → sb.release()
// B: sb.acquire() → 打印 → sa.release()
```
